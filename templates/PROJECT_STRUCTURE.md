# 파일 구조 계약

기존 저장소 구조를 먼저 사용한다. 아래는 권장 역할이며 빈 폴더를 의무적으로 만들지 않는다. 구조 변경은 계획과 검증 설정에 반영한다.

| 경로 | 역할 | 변경 원칙 |
|---|---|---|
| PLAN.md | 짧은 현재 전체 계획 | 단계 간 연결·승인만 |
| plans/<설명적인-단계>.md | 방법 탐색·DB·web 세부 계획 | 단계별 현재 상태 |
| EXPERIMENTS.md | 방법 설명표·성능표 | 두 표 제자리 갱신 |
| methods/<설명적인-방법>/ | METHOD.md, RESULTS.md, 설정 | 상세 방법·실험 근거 |
| DECISIONS.md, decisions/<주제>.md | 현재 결정표·선택 근거 | 이력은 Git |
| HANDOFF.md | 짧은 현재 인계 | 다음 행동·막힌 점 |
| verification.json | 요구사항과 자동 검사·구조 계약 | 실제 프로젝트용으로 구성 |
| tests/ | 단위·통합·전체 흐름·회귀 테스트 | 독립적인 예상값 사용 |
| runs/ | 실행·검증 원본 로그 | Git 제외, 덮어쓰지 않음 |

실제 서비스 코드·DB·web 경로는 승인된 구조 표에 추가하고 verification.json의 structure paths에 필요한 파일·디렉터리를 등록한다. 경로 검사는 파일 존재·종류만 확인하며 모듈 의존성·동작은 별도 테스트로 검사한다.
